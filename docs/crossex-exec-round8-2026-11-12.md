# crossex-exec 第八轮：参数化 + 按盘口/OI 定量 + 代码映射确认（2026-11-12）

用户确认：成交额门槛、每笔金额、总仓位等都写成参数，由用户在 taoli1“实盘”页填写或确认；代码不一致的交易对由程序识别、用户确认后才交易。

## 1. 参数（存 crossex-exec 数据库，前端可改）
| 参数 | 默认 | 下限 | 代码上限（页面不能超过） |
|---|---|---|---|
| min_quote_volume_usd 单所 24h 成交额门槛 | 1,000,000 | 100,000 | — |
| min_venues_with_volume 达到门槛的家数 | 2 | 2 | — |
| order_usd_max 单笔名义额上限 | 50 | 5 | 150（原硬上限） |
| depth_fraction 较薄腿开仓价容忍带内深度占比 | 0.20 | 0.01 | 0.50 |
| oi_fraction 两腿较小 OI 占比 | 0.0005 | 0.00001 | 0.005 |
| max_total_open_usd 全部未平名义额 | 600 | 0 | 600（原硬上限） |
| max_open_pairs 同时持仓对数 | 3 | 0 | 3 |
| max_equity_drop_usd 权益跌幅全平停机 | 150 | 10 | 150（原硬上限） |
| daily_loss_stop_usd / total_loss_stop_usd | 20 / 100 | 1 / 1 | 20 / 100 |
| 第六、七轮的开仓阈值（超额门槛、乌龙指各阈值、盘口时间差/年龄） | 现值 | — | 只能调严，不能调松 |

- 服务端校验范围，越界返回 400，不钳制、不部分生效。代码上限仍是常量，页面只能在上限内调整。
- 每次修改落库审计（旧值、新值、时间、来源），只影响之后新开的仓；已有持仓不受影响。读不到参数表时使用默认值并告警。
- 参数在每次开仓判定时读取（带版本号），发送前复核用同一版本。

## 2. 按盘口和 OI 定量
每笔名义额 = min(order_usd_max, depth_fraction × 较薄腿在开仓容忍带内的可成交深度, oi_fraction × 两腿较小 OI, 剩余总额度)，再按两腿公倍数步长向下取整。
- 低于任一腿交易所最小下单额/名义额则放弃，记 `size_too_small`。
- OI 用各所公开接口（核实官方文档字段与单位：张/币/USDT），读不到或超过 5 分钟没更新则放弃，记 `oi_missing`。
- trades/positions 记录 sizing 明细：depth_usd、oi_usd、各约束值、最终取哪一项。

## 3. 交易范围（白名单）
- 程序每小时用六所公开批量行情计算候选：达到成交额门槛的家数 ≥ min_venues_with_volume。
- 分类：币安合约目录 underlyingType=COIN 且不在 RWA/黄金/股票/ETF/商品列表中视为加密币；其他一律“需人工判断”。
- 状态：`candidate` → 用户确认 `enabled` / 排除 `excluded`。**只有 enabled 的才交易**，候选不会自动启用。已启用的币之后不再满足门槛时停开新仓（不强平），页面标出。
- 环境变量 CROSSEX_BASES 作为首次启动的初始 enabled 集合，之后以数据库为准。

### 3b. 已上市股票/ETF（用户 11-12：上市前的不列，已上市的要纳入）
- 类别：`crypto` / `listed_equity`（含 ETF）/ `pre_ipo` / `commodity`。pre_ipo（如 ANTHROPIC、OPENAI 及币安 PREMARKET 类）永不进入候选；commodity 本轮不纳入。
- listed_equity 一律不自动分类通过：候选页显示各所写法，用户确认时必须选定**标的市场**（v1 只支持 `US`=NYSE/Nasdaq 和 `KRX`=韩交所），选不了的不能启用。同一代码各所跟的标的不同（如 SKHYNIX 跟韩股或美国存托凭证）时，用户只确认跟同一标的的那几家，其余所不参与该币。
- 不限交易时段（用户 11-12：任何时段都可以，靠止损控制）。标的市场字段只用于确认各所跟的是同一标的。
- 其余条件（资金费差、基准平坦、乌龙指判定、定量、映射复核、止损、最长持仓）与加密币相同。
- 测试：pre_ipo 不进候选；未选标的市场不能启用；只启用跟同一标的的交易所。

## 4. 代码映射
- 识别同一币不同写法：前缀 1000/10000/100000/1000000/1M/K 等，按各所中间价比推算倍数，倍数与前缀不一致（偏差 >1%）的不列为候选。
- 状态 `pending` → 用户确认 `confirmed` / 拒绝 `rejected`。只有 confirmed 的映射可交易。
- 每次开仓前用两腿实时中间价复核价格比 = 倍数（偏差 ≤1%），否则放弃，记 `mapping_ratio_mismatch`。数量换算必须带倍数，测试要覆盖两个方向和步长取整。
- 已知陷阱写进测试：KO（可口可乐）≠ 1000×O；KAT ≠ K×AT。

## 5. 接口（契约文档同步，只加不删）
- GET /api/v1/config（当前值、默认、下限、上限、版本）；PUT /api/v1/config（部分更新，原子生效）；GET /api/v1/config/audit
- GET /api/v1/universe；POST /api/v1/universe/{base}/enable|exclude
- GET /api/v1/mappings；POST /api/v1/mappings/{id}/confirm|reject
- 写接口用独立令牌 CROSSEX_EXEC_ADMIN_TOKEN（与只读令牌不同），只读令牌调用写接口返回 403。请求体大小限制，参数类型严格校验。
- summary 增加 size_too_small / oi_missing / mapping_ratio_mismatch 放弃次数。

## 6. 测试
- 每个参数：边界内生效、越界 400、超过代码上限拒绝、审计记录、只影响新开仓、重启后保留。
- 定量：深度/OI/单笔/剩余额度四种约束各自成为最小项；低于最小下单额放弃；OI 缺失放弃。
- 白名单：候选不自动交易；排除后不开；掉出门槛停开不强平。
- 映射：未确认不交易；倍数换算两个方向；价格比偏差 1.01% 放弃。
- 不变量模拟器 3 种子各 ≥2400 回合全过（加入参数运行中变更、映射币种）；两条 unittest 全过。
