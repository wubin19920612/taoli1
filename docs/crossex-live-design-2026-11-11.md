# 小额实盘执行设计：Gate CrossEx 下单（2026-11-11）

状态：待拍板（§8）。未编码。

## 1. 目的与边界

- **目的**：用小钱实盘，量出模拟盘量不到的东西：真实成交价、两腿时间差、单腿成交的概率、CrossEx 转发延迟、真实手续费。
- **下单走 CrossEx + Bitget 直连**：Binance、Bybit、OKX、Gate、Aster 走 CrossEx（一个 Gate 账户、一套 key）；Bitget 不在 CrossEx 里，用 Bitget 自己的 API。两个账户用户都已开通（11-11）。
- **行情不用 CrossEx**：它本身没有订单簿接口，tickers 要鉴权且限 1 次/秒，太慢。价差判断全部用 taoli1 现有的实时数据（Gate WS、HL bbo），以及各交易所自己的公开 50 档盘口（fill-sim 已经在用）。CrossEx 只用来下单、查单、查成交、查账户。
- **真钱下单的开关由你本人打开**。Claude 只做设计、验收、dry-run 和只读核对。

**结论要说清楚**：
- 不用 Bitget，样本直接少一半；Bitget 直连后，去掉 INIT 还有 34 笔、平均 +20bp。
- CrossEx 能做的利润几乎全来自 INIT，而 INIT 的大价差本质上是在补偿资金费差（见 §5）。
- 去掉 INIT 后，每笔只剩约 +7bp。实盘再多付一点滑点或延迟，就可能是 0 或负数。

所以这次实盘的意义是**量出真实成交和模拟的差距**，不是赚钱。按每笔 100 美元算，赚亏都在几美元量级。

## 3. 结构

新服务 `crossex-exec`：独立的 Python 进程，只用标准库，和 fill-sim 一样跑在 taoli1-prod 上，单独的 systemd 服务，内存上限 MemoryMax=80M。

1. **触发**：轮询 taoli1 的 `/api/shadow/trades`，和 fill-sim 一样。
2. **复核**：并行拉两腿交易所的公开 50 档盘口，复用 fill-sim 的 `walk` / `opening`。按 100 美元吃单算出两腿的加权均价，再扣掉 CrossEx 的真实费率和资金费过滤（§5），净价差 ≥ 阈值才下单。
3. **下单**：两腿同时向 CrossEx 发 IOC 限价单。
   - 限价 = 吃到目标数量所需的最差一档价格，再加 3bp 容差。
   - `text` 用自己生成的唯一订单号，防止重复下单。
4. **确认**：CrossEx 下单先回一个受理确认（ACK），之后才有结果，所以要立即保存 `order_id`，然后每 200ms 查一次单，直到成交、撤单、失败或被拒。成交价和手续费从 `history_trades` 按时间窗口补拉。
5. **单腿处理**：如果两腿成交量不一样，立刻用 `reduce_only` 的 IOC 单把多出来的部分平掉，每次放宽 10bp，最多试 3 次。还平不掉就停止开新仓并告警。
6. **跟踪与平仓**：按 3s / 15s / 60s 的间隔拉公开盘口，按 §6 的规则平仓，平仓单也是两腿同时 IOC + `reduce_only`。
7. **对账**：每 60 秒用 `/crossex/positions` 和本地持仓对一次。不一致就停止开新仓并告警。

**和 fill-sim 对照**：同一个影子单，fill-sim 记模拟成交，crossex-exec 记真实成交。报告直接给出每笔的差：成交价差多少 bp、两腿时间差多少毫秒、单腿失败率。

## 4. 可交易范围

- 只做**永续对永续**，6 家：CrossEx 下的 Gate、Binance、Bybit、OKX、Aster，加 Bitget 直连。现货买入腿先不做（D2）。
- 一腿 Bitget、一腿 CrossEx 时，两边保证金各放各的，盈亏不能互抵：单边行情时亏的那腿可能先被强平，所以 Bitget 账户也单独按保证金率熔断。
- 币种映射：用 CrossEx 的 `rule/symbols` 和各交易所的原始代码逐个对应，只允许**精确匹配**的币，对不上的不做。
- 成交额 ≥500 万美元，和影子账本、fill-sim 一致。
- 黑名单：开仓前 24 小时内资金费率绝对值超过 0.5% 的币，INIT 现在就会被这条挡掉（见 D5）。

## 5. 资金费

fill-sim 的教训是：INIT 在不同交易所的资金费率差很大，结算一次就要付 1.7%–5.5%，价格上的大价差正是在补偿这个。

- **开仓前过滤**：任一条腿离下一次资金费结算不到 30 分钟，不开。
- **算进门槛**：把两腿资金费率差（按一个结算周期算）当成成本扣掉，扣完净价差仍 ≥15bp 才开。
- **结算前平仓**：持仓中任一腿离结算不到 5 分钟，就主动平仓，不跨结算。
- 资金费率用各交易所自己的公开接口拉，fill-sim 已经实现了。CrossEx 的 `/crossex/positions` 只用来对账。

## 6. 平仓与止损

| 条件 | 动作 |
|---|---|
| 价差收敛到开仓时的一半 | 止盈平仓（和模拟一致） |
| 价差反向扩大 ≥50bp，或浮亏 ≥1% 名义额 | **止损平仓** |
| 持仓满 2 小时 | 平仓（模拟里 9 小时以上的单子基本都是亏的） |
| 离资金费结算 <5 分钟 | 平仓 |
| 某条腿的盘口 60 秒拉不到 | 用另一条腿最后一次能成交的盘口，按更宽的容差平仓 |

## 7. 风控与熔断

| 项 | 初值 |
|---|---|
| 单笔名义额 | 100 美元（每条腿） |
| 同时持仓 | ≤3 对，同一个币只开 1 对 |
| 杠杆 | 3 倍，统一保证金模式 |
| CrossEx 里放的钱 | 你定，建议 300–500 USDT |
| 当日亏损 | ≥20 美元：当天停止开新仓 |
| 累计亏损 | ≥100 美元：全部平仓，服务停机，等你确认 |
| 保证金率 | 低于 300% 停止开新仓；低于 200% 全部平仓 |
| 失败率 | 连续 3 次单腿失败，或 1 小时内拒单率 >30%：停止开新仓 |
| 总开关 | `CROSSEX_LIVE_ENABLED` 默认 0；另有一个文件开关，删掉文件就立即停止开新仓 |

**清算顺序风险**：CrossEx 强平时先平多头，会先变成单边空头。所以保证金率阈值要定得远高于 100%。
