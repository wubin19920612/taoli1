## P0
1. **补平可能扩大裸露敞口**（engine.py:481、508）
   - 备用方案禁止“假设两腿都会成交、同时发出两笔减仓单”。
   - 改为串行：先发第一笔减仓，等它的**实际成交量**确定后，再按真实持仓重新算另一腿该减多少。
   - 每发出一笔之后都重新读两腿持仓。只有当裸露数量严格变小时才继续；否则停止补平、停止开新仓并告警。
   - 测试要复现审查给的场景：持仓 `1 / 0.999`，步长 `.1 / .001`，第一笔零成交。修复后裸露数量不得超过 `.001`。

## P1
2. **两腿各自复核，可能只发出一腿**（execution.py:69、policy.py:113）
   - 发单前的复核在**同一处只做一次**：用同一个时刻检查两腿盘口年龄和价差，结论同时适用于两腿。
   - 复核通过后，两个发送线程只负责发送，不再各自判断。
   - 测试：第一腿盘口 1.9 秒、第二腿 2.1 秒时，两腿都不发。
3. **费率和时间戳不是同一版本**（accounts.py:126、engine.py:54）
   - 每个合约的费率和它的生效时间放进同一个不可变对象，一次性替换发布。读取时一次取出整个对象。
   - 测试：旧费率不能借用新的时间戳通过检查。
4. **CrossEx 成交均价字段读错**（adapters.py:40）
   - 按官方订单详情，字段是 `executed_avg_price`，改正。相关测试的夹具也一起改正。
   - Bitget UTA 的订单均价字段同样对照官方文档核实一遍，交接里写明出处。
5. **前一天的浮亏会锁住新的一天**（engine.py:197、237）
   - 日损益 = 当天已实现盈亏 + 当天浮亏的**变化量**。每天 UTC 0 点时，把当时各持仓的浮亏记为当日基准。
   - 测试：昨天浮亏 −20，跨日后权益没有变化，新的一天不得被锁。
