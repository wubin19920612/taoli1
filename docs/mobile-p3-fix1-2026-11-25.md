# P3 推送修复 1（只读审查结论，2026-11-25）

基于 39c74f1。审查原文 `output/mobile-p3-review.log`（主仓库）。只改 `services/fcm.py`、`services/mobile_push.py`、`db/repositories.py` 及其测试。

1. **FCM 认证失败退避**（fcm.py:173）：401/403 或换证失败后进入熔断：1 分钟内不再发送/换证，之后指数退避到最长 15 分钟；成功一次即恢复。access token 缓存不因单条失败失效（只有 401 才失效）。RSA 签名放 `asyncio.to_thread`。测试：连续 10 条在 401 下最多 2 次 FCM 请求、1–2 次换证。
2. **扫描不被发送阻塞**（mobile_push.py:192）：扫描只负责检测并把消息放入有界队列（上限 200，满了丢最旧并记 warning）；单独的发送协程并发上限 4 发送。扫描周期不受 FCM 延迟影响。测试：FCM 挂起 5 秒时扫描仍按周期完成。
3. **大价差去重**（mobile_push.py:127）：去重键统一为 `big_spread:<规范化 symbol 或路线>`，普通和加急两条记录合并为一次推送（加急优先用 urgent 渠道）。测试：同一大价差两种记录 10 分钟内只推一次。
4. **通知 tag 不互相覆盖**（mobile_push.py:128）：无 card_id 时 tag 用 `<kind>:<规范化 symbol/路线>`。测试：两个不同标的 tag 不同。
5. **token 不进日志**（repositories.py:329）：SQL 参数里不直接出现完整 token：表主键改为 `token_hash`(sha256) + `token` 列仍存原值但所有 WHERE 用 hash；同时确保本模块自身日志只打 token 末 6 位。旧表若已存在需兼容迁移（本表未上线，可直接按新结构建；仍要 `CREATE TABLE IF NOT EXISTS`）。测试：开启 DEBUG 日志注册后，日志不含完整 token。
