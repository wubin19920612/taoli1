# 行情预处理性能交接

日期：2026-10-09。本轮范围是采集器发布前后的别名和指数观察名单匹配，沿用同一对话持续优化。

## 目标与基线

- 分支 `codex/frontend-localization-polish`；本地基线 `6e1202c`，生产基线 `16a1185fe7cbb156255bc32300cee191ed2dd976`。
- 每条未直接命中的行情原先扫描整个别名表寻找唯一 DEX；指数过滤则针对每个市场重复规范化所有观察标的。
- 目标：减少重复扫描，保持真实 DEX、原始市场、价格/数量倍率、规则优先级、配置即时更新、市场对象及排序不变。

## 实现与边界

- `backend/app/services/symbol_aliases.py::SymbolAliasResolver`：在现有规则覆盖/去重后，为隐式 DEX 匹配建立当前解析器实例内的索引。唯一匹配存规则对象，多个 DEX 存 None 表示歧义；“存在但歧义”的精确市场规则不会回退通用规则。显式 DEX、直接命中和反向 canonical 查找流程保持原样。
- 索引每次随解析器创建，没有跨请求/跨配置缓存。所有返回对象仍引用原规则；没有按规范化 ticker 合并不同 DEX 的市场。
- `backend/app/services/collector.py::_index_component_markets`：观察名单每次读取并规范化一次，市场和原始别名各自按原顺序检测集合成员关系。返回原市场对象，保留不同 DEX/原始市场及输入顺序。
- 对异常观察字符串回退旧版惰性匹配，保留短路和错误顺序。即使名单为空，也保留原有市场字符串规范化/校验，因此没有用无条件提前返回改变异常输入行为。
- 不更改采集时序、通知、数据库、历史保留、轮询频率、交易判断或市场数据校验。

## 验证与基准

- 冻结旧 direct-alias 查找为 `backend/tests/symbol_aliases_reference.py`；24 套配置 × 280 种交换所/类型/DEX/标的组合，共 6,720 组 resolve 和 alias_for 比较通过。
- 另验证精确规则歧义不回退、覆盖规则先去重、内置规则覆盖后恢复、配置重新创建生效、完整行情字段/顺序/对象所有权一致。
- 观察名单的 27 组有效/异常组合与旧过滤器比较结果对象/顺序或异常一致；另验证配置变更、空名单和不存在过滤器时的返回语义。
- 别名、观察名单差分、既有别名、采集器及计算链合计 **137 项通过**，修改文件和基准脚本 Ruff 通过。补充指数监控及真实品种查询回归 **38 项通过**；旧模型存在 11 条 utcnow 弃用警告，本轮未更改时间模型。
- `python script/benchmark_market_preprocessing.py --markets output/spread-engine-markets-20261009.json`：11,840 条公开行情。公开快照已经带别名元数据，测量从原始标记及倍率还原 2,798 条派生输入以避免重复缩放；这是固定派生计算样本，不声称完全复现适配器原始响应。前后处理同一份输入，全部输出字段及顺序一致。
- 当前 1 条用户别名：11.226 → 7.800 ms（约 -30.5%）；1 条行情的小样本均约 0.0033 ms。80 条合成别名输入：30.976 → 8.046 ms，这组是扩展规模测量，不是线上配置。
- 指数观察名单实际为空：5.562 → 4.362 ms（约 -21.6%）；合成 1/30 个标的：9.479/95.450 → 4.506/4.973 ms，所选 16/324 个市场对象顺序一致。
- 当前别名处理峰值 Python 分配 97,653/97,245 bytes，差异不大；单行情索引额外约 160 bytes。收益主要为减少 CPU 扫描，不声称整站延迟同比下降或内存显著减少。
- 结果 `output/market-preprocessing-benchmark-20261009.json`，公开源文件原 SHA 见价差引擎交接。早期未还原输入的测量另保留，不混作本轮最终基准。
